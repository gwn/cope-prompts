Submit a change proposal for the issue document: a title and description, like a Git commit message, plus change operations, each with a short label. The accepted changes become a new version, and its title and description are the issue's history. Operations: set_field (phase; title and icon only to rename an issue already named), replace_section, add_section, remove_section, add_item (the runtime assigns the id), update_item (by id, e.g. a7). Nothing changes until the user accepts it. Call it on your own when something worth keeping has settled. If the user asked for the update in their own words, put those words in user_request, quoted exactly from their latest message.
